# 제품 연결 관리 GUI 1단계

## 한쪽에서 연결 해제

agent generation 11부터 인증된 연결에서 한쪽의 `연결 해제`를 누르면 상대도
재연결을 멈추고 입력 정리 후 `LOCAL`로 돌아간다. 양쪽 PC를 함께 업데이트해야 한다.
페어링은 유지된다. 네트워크 장애나 프로세스 비정상 종료 때의 자동 재연결은 유지한다.
이미 연결이 끊겨 해제 신호를 전달할 수 없으면 상대에서도 해제해야 할 수 있다.
진단의 `peer_disconnect_requested`는 상대의 명시적 해제 수신을 나타내며,
`disconnect_notification_failed`는 해제 알림 전송 실패다. 입력 정리 실패는 별도로 남는다.
상세 계약은 [ADR 0038](../adr/0038-explicit-product-disconnect.md)을 따른다.

`krasis-control.exe`는 제품 resident agent를 준비하고 인증된 loopback API를 사용한다.
기존 Phase 0 launcher와 별개이며 저장된 제품 신뢰·연결 설정을 재사용한다.

- 유일한 별칭을 가진 미철회 peer 목록, 상태 새로고침, 연결, 연결 해제를 제공한다.
- `LOCAL`에서만 선택한 peer의 연결을 요청한다. 요청 성공을 `CONNECTED`로 추정하지 않는다.
- 연결 해제는 trust 목록 조회 성공에 의존하지 않는다. 최종 권한·활성 상태 판단은 agent가 소유한다.
- `기기 등록 해제`는 기본 선택이 취소인 확인 창을 거친다. 확인한 fingerprint가 현재 목록에도
  있어야 하며 LOCAL에서만 요청한다. 별칭이 같은 다른 기기로 바뀌면 취소한다. 로컬 trust만
  철회하고 상대 PC의 저장소·자격 증명·로그는 삭제하지 않는다. 다시 사용하려면 재등록한다.
- 시작 준비와 API 작업은 UI 메시지 루프 밖에서 최대 20초 context로 실행한다. 한 번에 한 요청만 처리한다.
- 새 요청마다 현재 endpoint credential을 다시 읽는다. 오류 원문, path, token, certificate는 표시하지 않는다.
- 창 닫기는 트레이 등록 성공 시 관리 창만 숨긴다. agent/session은 유지된다.
- PIN 기반 최초 페어링과 등록 대기 중인 기기 검색을 제공한다. 일반 기기 자동 재발견·재연결,
  자유로운 다중 화면 배치 편집은 별도 범위다.

## 두 PC의 좌우 배치 변경

연결을 해제하고 목록에서 상대 기기를 선택한 뒤 `상대가 왼쪽` 또는 `상대가 오른쪽`을 누른다.
이 PC에서 상대 화면으로 나가는 경계만 저장하며 IP 주소·포트·신뢰 권한은 바꾸지 않는다.
상대 PC에서도 반대 방향을 선택한 뒤 다시 연결한다. 설정은 다음 연결부터 적용되며,
상대 설정을 원격으로 변경하거나 물리적 위치를 자동 감지하는 기능은 아니다.

저장된 연결 설정이 없는 기기는 먼저 PIN으로 등록한다. 주소가 손상되거나 기기의 식별자가
바뀌면 저장을 거부한다. 활성 연결 중에는 agent가 변경을 거부한다. AgentGeneration 5부터
이 기능을 지원하며, 새로고침 시 이전 agent는 idle 상태에서만 교체된다.

## 경계 재진입 여유

연결을 해제하고 상대를 선택한 뒤 `재진입 32px (기본)`, `재진입 64px`, `재진입 128px` 중
하나를 누른다. 전환 후 경계에서 이 거리만큼 안쪽으로 이동해야 다시 전환할 수 있다.
값이 커지면 즉시 왕복을 줄일 수 있지만 재전환에 더 많은 이동이 필요하다. 물리 픽셀 기준이며
지연시간이나 고배율 환경의 사용성을 보장하는 값은 아니다. 각 PC에 개별 저장하고 다음 연결부터
로컬 출구와 복귀 경계에 같은 값을 적용한다. 주소·좌우 방향·신뢰 권한은 유지한다.

기존 설정은 32px로 읽는다. 저장 형식에 선택적 `rearmDistance`가 추가되므로 새 설정을 저장한
뒤에는 Generation 6 이상을 사용한다. 이전 agent/CLI는 알 수 없는 필드를 거부할 수 있으므로
ZIP의 실행 파일들을 함께 교체한다. CLI의 전체 `connection set`은 재진입 값을 기본으로 초기화한다.
화면 폭보다 큰 재진입 값은 연결 준비 단계에서 거부하며 자동으로 더 작은 값으로 바꾸지 않는다.

## 트레이에서 관리

창의 닫기 버튼을 누르면 트레이에 남는다. 작업·PIN 등록 중에는 완료나 취소 후 닫도록 안내한다.
트레이 아이콘을 선택하면 창이 다시 열리고, 오른쪽 메뉴에서 `연결 해제` 또는
`연결 유지하고 관리 앱 종료`를 선택할 수 있다. 관리 앱 종료는 에이전트를 끄거나 연결을
끊지 않는다. 연결 중지는 별도 `연결 해제`로 수행한다. 종료 시 활성 PIN 등록은 취소를 요청한다.

툴팁은 인증된 agent 응답의 상태를 고정 문구로 표시하며, 상태 조회 실패를 연결 성공이나
로컬 복귀로 추정하지 않는다. 트레이 메뉴를 연 동안 주기적 조회는 잠시 멈추고, 메뉴 선택
후 현재 busy/closing 상태를 다시 확인한다. 탐색기의 `TaskbarCreated` 메시지에서 아이콘을
재등록한다. 트레이 등록·버전 설정·갱신 실패 시 창을 표시하며, 아이콘 없이 숨기지 않는다.
트레이가 없는 경우 닫기는 기존 관리 앱 종료 동작을 사용한다. 자동 시작 등록은 하지 않는다.

Win32 구조와 버전 설정은 [Microsoft Shell_NotifyIconW 문서](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shell_notifyiconw)를 따른다.
실제 탐색기 재시작·트레이 키보드 조작·고배율 화면은 수동 검증 대상이다.

## 에이전트 자동 준비

더블클릭, 새로고침 버튼, 연결 요청 시 에이전트를 준비한다. 없으면 실행 파일과 같은 폴더의
`krasis-agent.exe`를 콘솔 없이 한 번 실행하고 준비 완료를 기다린다. 현재 작업 폴더나 PATH에서
실행 파일을 찾지 않는다. 실행 전 SHA256SUMS.txt의 GUI·agent 해시를 검사한다. 해시는 손상이나
파일 혼합을 감지할 뿐 배포자 인증이나 코드 서명을 대체하지 않는다.

호환되는 동일/상위 generation은 재사용한다. runtime API가 없는 기존 v1 agent도 재사용하며
강제 종료하지 않는다. lifecycle 지원 agent가 요구 generation보다 낮으면 인스턴스 nonce를
지정해 idle-only 종료를 요청한다. agent가 잠금 안에서 연결·페어링 부재를 확인한 뒤 종료하며,
GUI는 기존 agent 소유권 잠금이 해제된 뒤 새 agent를 실행한다. 활성 세션은 먼저 연결 해제해야 한다.
프로토콜 불일치, 인증 오류, 번들 손상은 자동 종료나 자격 증명 삭제로 우회하지 않는다.

동시 시작은 별도 named mutex로 직렬화한다. 주기적 상태 갱신은 agent를 시작하지 않으므로
명시적 종료 후 무한 재시작하지 않는다. 창을 닫아도 agent는 유지된다. 인터넷 업데이트,
시작 프로그램·서비스 등록, 방화벽 변경은 수행하지 않는다. AgentGeneration은 호환 제품 변경 시
의도적으로 올리는 로컬 배포 세대이며 Git build revision과 구분한다.

## 자동 로그

`%LOCALAPPDATA%\Krasis\diagnostics`의 `agent.jsonl`, `control.jsonl`에 시작·종료,
준비 실패, 연결 시작·실패·상태 전이를 기록한다. 각 파일은 256KiB까지 쓰고 이전 파일 하나
(`*.previous.jsonl`)만 남기므로 정상 운용 시 총 1MiB 이하이다. 인터넷 전송은 없다.
고정 이벤트 코드, UTC 시각, PID, build revision과 아래 경계 요약만 허용하며 오류 원문, 키 입력, 마우스 이동 경로,
별칭, IP, 토큰, 기기 키는 기록하지 않는다. raw stderr나 메모리 덤프도 수집하지 않는다.
기록은 제한된 큐에서 처리하여 입력 경로에서 디스크를 기다리지 않는다. 큐 초과·쓰기 실패는
GUI 경고 또는 agent diagnostics의 `log_incomplete` counter로 알린다. 정상 종료는 최대 2초
drain하며 강제 종료·전원 차단 직전의 큐 항목은 유실될 수 있다. 저장 권한 오류나 디스크 고장은
파일 기록을 보장할 수 없다. 두 번째 동시 GUI는 로그 소유권 경고를 표시할 수 있다.

AgentGeneration 2부터 agent 로그, 3부터 PIN 등록을 지원한다. 낮은 generation은 idle 시 자동 교체한다.
runtime API가 없는 더 오래된 agent를 재사용하는 경우 control 로그만 새로 기록된다.

## 진단 내보내기

`진단 내보내기`를 누르면 `%LOCALAPPDATA%\Krasis\diagnostics\support-latest.json`에
최근 이벤트 기록을 저장한다. 하단 경로를 선택해 복사할 수 있다. 내보낼 때마다 이전 진단
파일 하나만 교체하므로 과거 자료가 필요하면 먼저 별도 보관한다. 자동 업로드는 하지 않는다.
네 개의 지정 로그만 파일당 256KiB까지 읽고, 허용된 이벤트 코드와 정규화한 UTC 시각만
다시 구성한다. 경계 요약은 지정된 숫자 필드와 LEFT/RIGHT 값만 검증하여 추가한다.
PIN, 별칭, IP, PID, build 문자열, 키, 토큰, 원문 오류는 내보내지 않는다.
identity/trust/control 폴더 및 다른 파일은 수집하지 않는다.

AgentGeneration 7은 `boundary_summary` 이벤트를 연결 실행 시작과 정상 반환 시 기록한다.
`krasis.support/v1`의 선택적 `boundary` 필드이며, 이전 이벤트 형식은 유지된다.
`left/top/width/height`는 실제 경계 설정에 사용한 화면 값이다. `physical_width/physical_height`는
현재 기본 디스플레이의 물리 픽셀 크기(조회 실패 시 0), `dpi_awareness`는 프로세스 DPI 인식 값
(-1 조회 불가, 0 비인식, 1 시스템, 2 모니터별)이다. 배율 백분율이나 훅 스레드의 DPI 상태를
직접 측정한 값은 아니다. `edge/gap/rearm`은 적용한 경계 설정이다.
`candidates`는 경계 후보 판정의 누적 횟수이며 성공한 제어권 전환 횟수가 아니다.
`last_offset`은 마지막 후보 X에서 해당 화면 끝 X를 뺀 값이며 후보가 없으면 0이다.
일반 이동 좌표, Y 좌표, 키 입력은 저장하지 않는다. 연결 중에는 시작 요약만 존재할 수 있으므로
재현 후 연결 해제하고 내보낸다. `complete: true`는 연결 실행 반환 시점의 집계임을 뜻하며
성공이나 오류 해결을 뜻하지 않는다. 강제 종료 시 최종 집계는 없을 수 있다.
이 진단은 DPI 설정이나 경계 동작을 변경하지 않는다.

AgentGeneration 8부터 입력 에이전트와 crash guard는 시작 직후 모니터별 DPI 인식을
초기화한다. 경계 감지, 커서 진입, 복귀의 Windows 좌표를 물리 픽셀 기준으로 맞추며,
관리 GUI의 표시 배율은 변경하지 않는다. v2가 불가능하면 모니터별 v1을 사용하고,
둘 다 설정·확인할 수 없으면 에이전트 시작을 중단한다. 폭에 1.25를 곱하는 고정 보정은 없다.
125%/1920×1080 환경의 새 진단은 `width:1920`, `height:1080`, `dpi_awareness:2`가
기대값이다. 양쪽 연결을 해제한 뒤 새 관리 앱을 실행하면 이전 세대의 에이전트를 교체한다.
실제 두 PC에서 화면 끝 전환과 복귀는 별도로 확인해야 한다.

AgentGeneration 9는 재시도 대기 진입마다 고정된 `reconnect_*` 원인 이벤트를 남긴다.
`reconnect_acquire_failed`는 연결 획득 실패이며 활성 제어 중 단절과 구분한다.
`reconnect_remote_eof`는 상대가 스트림을 닫았다는 뜻이지 상대가 정상 종료했다는 증거는 아니다.
`reconnect_read_io_failure`, `reconnect_*_write_failed`, `reconnect_*_dispatch_failed`는
읽기, 쓰기, 메시지 처리 실패를 구분한다. capture/focus 관련 코드는 입력 캡처·포커스 단계의 실패다.
`heartbeat_timeout_observed`는 반환 오류에 하트비트 만료가 포함됐음을 독립적으로 표시한다.
다른 정리 오류가 주된 원인 코드로 선택돼도 이 표시는 남으며, 원인이 네트워크인지 스케줄링인지까지
확정하지는 않는다. 알 수 없는 사유는 `reconnect_session_unknown`으로 기록한다.
로컬 연결 해제 요청은 `disconnect_requested`로 남긴다. 두 PC의 시계가 다를 수 있으므로
각 장치 내 이벤트 순서를 우선 비교한다. 원문 오류·주소·키 입력은 수집하지 않는다.
이번 진단 추가는 하트비트 주기, 만료 제한, 재시도 정책을 변경하지 않는다.

AgentGeneration 10은 정상 복귀 직후 늦게 도착한 같은 retired session의 하트비트를
제품 수신 루프에서도 안전하게 폐기한다(ADR 0020). 이전 수신 루프는 활성 liveness가
없다는 오류를 먼저 반환하여 정상 복귀를 재연결로 바꿀 수 있었다. 활성 lease의 만료 검사,
다른 session 거절, held input 해제는 유지하며 timeout 값은 변경하지 않는다.
하트비트 수신 observer의 집계에는 성공적으로 폐기한 프레임도 포함되므로 수신 횟수를
liveness 갱신 횟수로 해석하지 않는다. 이 수정은 캡처 실패나 잠금 지연 원인을 해결하지 않는다.

에이전트를 켜거나 연결을 바꾸지 않고 저장하므로 오프라인에서도 사용할 수 있다. 없는 로그,
손상되거나 너무 큰 기록, 쓰기 도중의 마지막 줄은 `incomplete: true`로 표시한다. 이 자료는
이벤트 이력이며 현재 연결 상태나 완전한 크래시 보고서가 아니다. 기록 시각은 사용 패턴을
드러낼 수 있으므로 공유 전에 내용을 확인한다. PIN 등록 중에는 내보내기를 비활성화한다.
저장 실패 시 기존 진단 파일은 유지하고 저장 공간·폴더 권한 확인 안내를 표시한다.
임시 파일을 동기화한 뒤 교체하지만 전원 차단 시 저장 완료까지 보장하지는 않는다.

연결 문제가 있으면 먼저 `연결 해제`로 로컬 상태로 복귀하고 `새로고침`을 누른다. 상대가
검색되지 않으면 상대 PC의 PIN 유효 시간과 Wi-Fi·방화벽을 확인한다. 계속 실패하면 진단
파일과 화면에 표시된 상태를 함께 전달한다. 기기 키나 control 폴더를 공유하지 않는다.

## PIN으로 새 기기 등록

왼쪽 PC에서 `PIN 만들기`, 오른쪽 PC에서 `주변 기기 찾기`를 누르고 상대를 선택한 뒤
6자리 PIN을 입력한다. 버튼 위 안내대로 등록은 양쪽 키보드·마우스 제어 허용을 포함한다.
등록 완료 후 연결 설정(초대한 PC는 LEFT 장비/출구 RIGHT, 참여 PC는 RIGHT 장비/출구 LEFT,
입력 포트 45872)을 저장하고 GUI가 연결을 요청한다. 물리적 위치를 감지하는 기능은 아니다.
기존 신뢰와 페어링을 삭제하지 않으며 기존 기기는 다시 등록할 필요가 없다.

검색은 초대한 PC가 2분 동안 여는 UDP 45873 응답만 사용한다. 발견 결과는 신뢰의 근거가 아니며
PIN은 광고하지 않는다. 등록은 TCP 45871의 전용 TLS ALPN `krasis-pin/1`을 사용해 기존 SAS
페어링으로 조용히 전환되지 않는다. 방화벽 허용은 OS 정책에 따르며 앱이 규칙을 변경하지 않는다.
AP 격리·VPN·여러 NIC 환경에서는 발견되지 않을 수 있다. OS 네트워크 권한이나 방화벽 승인은
사용자가 해야 한다. 등록 취소 또는 완료·실패·만료 시 광고와 작업을 종료한다.

PIN은 임의의 6자리, 일회용, 최대 2분이며 실패하면 폐기하고 30초 후 새 초대를 만들 수 있다.
PAKE는 [schollz/pake v3](https://github.com/schollz/pake)의 P-256 구현을 사용한다.
양방향 키 확인은 TLS exporter와 초대 ID에 묶어 다른 TLS 연결로 중계한 증명을 거부한다.
입력한 PIN, 원문 오류, PAKE 키는 로그·파일에 저장하지 않는다. 개발 테스트 빌드이며 독립적인
암호 보안 감사를 받았다는 주장은 하지 않는다. 큐·강제 종료·분산 저장 실패 시 양쪽 결과를 확인한다.

## 검증 경계

projection과 요청 테스트, Windows GUI 컴파일 및 ZIP 구성 확인은 자동 검증한다.
GUI 실제 클릭·글꼴·고배율 화면 레이아웃은 수동 확인 대상이다. 자동 검사에서 GUI나 입력 agent를
실행하지 않는다. 새로운 입력 경로나 신뢰 저장 형식은 추가하지 않는다.

기존 CLI 묶음에 대해서 사용자가 A↔B 포인터 전환, 키보드 입력, 연결 해제의 정상 동작을 보고했다.
이는 해당 두 장비의 기본 수동 확인이며 GUI 검증이나 잠금·절전·관리자 앱 검증을 대신하지 않는다.
