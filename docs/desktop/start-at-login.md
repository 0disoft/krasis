# Windows 시작 시 실행

앱 아래쪽의 체크박스로 켜고 끈다. 최초 기본값은 켜짐이다.
로그인 후 사용자 계정의 Run 항목이 고정 복구 CLI를 실행하고,
검증된 마지막 Krasis 버전을 트레이에서 시작한다. 업데이트 뒤에도
등록 경로는 유지되며, 보호 입력 서비스의 시작 설정은 변경하지 않는다.

마지막 연결 상대의 별칭과 fingerprint를 사용자 전용 파일에 저장한다.
로그인 시작에서 현재 페어링 정보가 둘 다 일치하고 에이전트가 LOCAL인 경우에만
연결을 요청한다. GUI와 CLI가 같은 에이전트에서 복원 상대를 저장한다.
명시적인 연결 해제는 복원 상대를 지우며, 정상 종료와 업데이트 교체는 유지한다.
로그인 전 Windows 잠금 화면에서 관리 앱을 실행하지 않는다.

g263의 로그인 전 연결은 자동 시작 서비스와 별도 관리자 승인으로 동작한다.
양쪽 g263 적용 후 각 PC의 기존 peer 별칭으로 `krasis-install --prepare-login PEER`를
한 번 실행하면 v2 승인이 사용자 해제까지 유지된다. 인증서는 기존 역할 키로
자동 갱신하며 매달 관리자 확인을 받지 않는다. g262의 기한 있는 v1 승인은
한 번 명시적으로 전환해야 한다. 자세한 검증·철회 정책은 ADR 0070을 따른다.

등록 실패는 설정 화면에 표시한다. 설정 저장에 실패하면 이전 Run 설정으로
복원한다. 해제한 옵션은 버전 갱신 후에도 유지한다.

자동 시작이 켜져 있으면 로그인한 사용자 권한의 예약 작업이 1분마다
고정 CLI의 `app ensure --json`을 실행한다. 에이전트가 응답하거나 단일 인스턴스
소유권이 남아 있으면 다시 실행하지 않는다. 둘 다 없을 때만 마지막 검증된 앱을
트레이에서 복구한다. 앱 경로가 변조되거나 설정을 읽지 못하면 복구를 중단한다.
`safe-stop`은 자동 복구를 일시 중지하며, 사용자가 앱을 다시 실행하거나 다음
Windows 로그인에서 앱이 시작하면 해제된다. 자동 시작 옵션을 끄면 예약 작업도 제거한다.
관리 앱만 종료하고 에이전트를 유지한 경우 관리 앱을 임의로 다시 띄우지 않는다.

사용자 계정별 예약 작업은 관리자 권한과 암호를 요청하지 않는다. 같은 이름의
작업이 다른 실행 경로·계정·권한·실행 주기를 사용하면 덮어쓰지 않고 실패를 표시한다.
작업 등록 실패 때문에 기존 입력 연결을 종료하지 않는다.

시작 메뉴의 Krasis 바로가기는 고정 복구 CLI를 사용한다. 더 오래된 버전을
실행해도 최신 실행 기록과 CLI를 덮어쓰지 않는다. 검증한 바로가기의 내용이 그대로면
매번 PowerShell로 재등록하지 않는다. Codex 같은 터미널의 작업 그룹에서 시작한
앱은 사용자 세션을 유지하는 독립 실행 경로로 분리한다. 이 경로를 사용할 수 없으면
실행 성공으로 보고하지 않는다.
