# PIN 창 입력 시험

이 시험은 B 노트북의 관리자 PowerShell과 Windows 보안 PIN 창에서 새 입력 경로가 실제로 작동하는지 확인합니다. 자동업데이트는 시험 파일만 전달합니다. 연결 중 PIN 창 제어 기능은 아직 추가되지 않았습니다.

1. A에서 `dist/workspace/g63/krasis.exe`를 실행하고 **기기 업데이트**를 누릅니다. B가 g60이면 g61 전환 묶음이 먼저 전송됩니다. `dist/workspace/g61` 폴더도 함께 보관해야 합니다. B의 제목과 업데이트 상태가 g61로 바뀌었는지 확인합니다.
2. A에서 **기기 업데이트**를 한 번 더 누릅니다. B가 g61이므로 g63 묶음이 전송됩니다. g63 묶음에는 시험용 MSIX와 공개 인증서가 함께 전송되지만, 자동 설치나 인증서 신뢰 등록은 하지 않습니다. B에서 시험하려면 현재 실행 중인 Krasis의 폴더에 있는 두 파일을 이용하세요.
3. B에서 [시험 패키지 안내](../../experiments/brokered-input/README.md)에 따라 인증서 지문을 확인하고, 시험용 공개 인증서를 신뢰한 다음 MSIX를 설치합니다. 이 로컬 설치는 업데이트가 대신하지 않습니다. 시험을 마치면 패키지와 시험 인증서를 제거합니다.
4. B의 실제 화면에서 관리자 PowerShell과 PIN 창을 각각 시험합니다. **PIN은 입력하지 않습니다.** API 반환 코드와 별개로 Esc 또는 클릭이 실제로 적용됐는지 확인합니다.

기존 트레이의 **PIN 창 입력 시험**은 관리자 권한 `SendInput` 경로를 시험하는 별도 도구입니다. 아래 결과 코드는 그 기존 시험에만 해당합니다.

| 결과 코드 | 뜻 |
| --- | --- |
| `dialog_dismissed_candidate` | Esc 전송 뒤 PIN 창이 전면에서 사라짐. 실제로 닫혔는지 확인 필요 |
| `dialog_still_open` | Esc 전송 뒤에도 PIN 창이 전면에 있음 |
| `dialog_not_observed` | 2분 안에 대상 PIN 창을 확인하지 못함 |
| `desktop_unavailable_or_changed` | 입력 화면이 바뀌었거나 화면을 확인하지 못함 |
| `foreground_identity_unknown` | 전면 창의 실행 프로그램을 확인하지 못함 |
| `other_foreground` | 시험 종료 때 다른 프로그램 창이 전면에 있었음 |
| `no_foreground` | 전면 창을 찾지 못함 |
| `escape_send_failed` | Esc 입력 전송 실패 |
| `not_elevated` | 관리자 권한으로 실행되지 않음 |

이 시험은 별도의 일회성 프로세스로 실행되며 평소 에이전트를 새로 시작하거나 A와 B를 연결하지 않습니다. 창이 닫히더라도 A의 마우스와 키보드가 B의 PIN 창에서 실제로 작동한다는 뜻은 아닙니다. 그 기능은 시험 결과를 확인한 뒤 별도로 구현해야 합니다.
