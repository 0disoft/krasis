## 확인된 결과

- source boundary intent `48` 중 `46`이 승인됐고 두 건은 reconnect 공백에서 `droppedNotReady`였다.
- 승인된 `46`회는 request, grant apply, source activation, capture activation, commit, revoke를 모두 완료했다.
- foreground fallback은 `44/44` 성공했다.
- exact focus restore 실패 `14`회는 post-hide `unavailable` `14`회로 끝났고 capture retention은 없었다.
  focus restore 실패가 source-capture terminal failure로 바뀌지 않았으므로 ADR 0030의 변경은 실기에서도
  작동했다.
- HP15는 entry와 return arm `46/46`, pointer `3851`, wheel `127`, button down/up 각 `2`를 injection failure
  없이 적용했다.
- gram13은 pointer `4358`, wheel `127`, button down/up 각 `2`를 source send 성공으로 기록했다.
- 양쪽 최대 receive gap은 gram13 `753ms`, HP15 `850ms`로 timeout보다 작았다.
- gram13 supervisor는 active `8`, session failure `8`이며 모두 `peer-reader/read/remote_eof`였다.
- HP15 supervisor는 active `8`, session failure `7`이며 모두 generic
  `peer-session/runtime/component_failed`였다.

## 판정

v20은 focus restore 실패가 연결 재생성을 직접 일으키던 결함을 제거했다. 하지만 실행 중 peer connection이
여덟 번 교체됐고 그 사이 boundary 두 건이 버려졌다. pointer source send와 destination apply 차이 `507`개가
정상 retired late-frame drain인지 queue backlog 또는 dispatch failure인지 v20 evidence만으로는 구분할 수 없다.
따라서 이 실행은 제품 acceptance 통과가 아니라 ADR 0031의 v21 진단 계측 근거다.
