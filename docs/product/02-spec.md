## MVP 범위

- 같은 사용자가 소유한 Windows 노트북 두 대
- 노트북마다 활성 디스플레이 하나
- 좌우 배치와 양방향 경계 전환
- 키보드, 포인터 이동, 휠, 기본 마우스 버튼 전달
- 로컬 네트워크 안에서의 기기 페어링, 상호 인증, 재연결
- tray GUI에서 연결 상태, 상대 기기, 배치, 안전 상태를 확인하고 설정
- CLI에서 상태 확인, 진단, 페어링 및 연결 해제
- 선택한 peer와 명시적으로 켠 텍스트·이미지·파일·폴더 클립보드 공유
- 선택적 보호 입력 설치와 승인된 peer를 통한 개발 빌드 업데이트
- 기본으로 켜진 Windows 로그인 자동 시작·종료된 에이전트 복구
- 배포 공개키를 구성한 빌드의 서명된 GitHub 릴리스 자동 업데이트

## MVP 제외

- 세 대 이상 또는 다중 모니터 토폴로지
- 화면·오디오 공유와 클립보드 외의 일반 파일 동기화
- 인터넷 중계, 클라우드 계정, 원격 측정
- 로그인 화면과 Windows 보안 데스크톱
- portable 입력 경로에서 관리자 프로그램·Windows PIN 창의 입력 보장
- Windows 이외 운영체제

## 핵심 동작

### 페어링 기기를 통한 개발 빌드 업데이트

- 업데이트 창은 양쪽 버전·업데이트 가능 여부·전송 진행을 우선 표시한다. 빌드 식별자와 수신 권한 설정은 접힌 상세 정보에 두고, 전송을 막는 상태는 기본 화면에서 설명한다. 정상인 보호 입력 설치 상태는 이 창에 반복 표시하지 않는다.
- 수신 PC에서 선택한 페어링 기기에 업데이트 공급 권한을 한 번 명시적으로 부여한다. 입력 제어 권한과 별개이며 해제할 수 있다.
- 송신 PC의 관리 앱에서 현재 배포 묶음을 전달한다. 파일 검증과 별도 폴더 저장 이후 입력 연결을 안전하게 해제하고 새 관리 앱과 에이전트를 실행한다.
- 현재 개발 빌드는 배포자 서명이 없으므로 허용한 PC를 코드 공급자로 신뢰한다는 점을 알린다. 공식 서명된 배포본으로 표시하지 않는다.
- 최초 지원 버전은 양쪽에 수동 설치해야 한다. 수신 측 관리 앱은 창 또는 트레이에서 실행 중이어야 자동 적용된다.
- 이전 실행 파일과 페어링 정보는 보존한다. 전송 완료와 새 에이전트 실행 확인은 별도로 표시·기록한다.
- 새 버전을 직접 실행하면 기존 연결을 안전하게 해제하고 관리 앱·에이전트와 이미 설치된 보호 입력을 갱신한 뒤 같은 신뢰 기기로 재연결한다. 보호 입력 갱신에 필요한 Windows 관리자 확인은 유지하며, 취소·실패 시 일반 입력을 복구한다. 설치 결과가 미확정이면 재설치와 재연결을 중단한다.
- 업데이트 후 재연결은 초기 준비가 끝난 뒤 관리 앱의 네이티브 관리 루프가 최대 3회·90초 동안 시도한다. 같은 배포 버전과 저장한 기기 지문을 확인하며, 연결 중에는 중복 요청하지 않는다. 기기 목록 조회 실패와 신뢰 변경을 구분하며, 결과가 불명확한 연결 요청은 조회만 계속하고 재전송하지 않는다. 앱 또는 CLI의 연결 해제·다른 기기 선택·앱 종료·신뢰 변경·확정된 설치 실패가 발생하면 중단한다. 에이전트는 수동 해제 이후 도착한 자동 재연결 요청을 거절한다.
- 일반 자동 복구·화면 변경 복구·보호 입력 갱신·업데이트 실패 후 복구도 같은 수동 해제 보호를 사용한다. 갱신용 임시 해제는 기존 수동 해제 상태를 지우거나 새로 만들지 않는다. 구버전 에이전트를 교체할 때는 기존 해제 명령을 사용하며, 교체 실패로 구버전이 남으면 수동 연결이 필요할 수 있다.

### 입력 제어

설정 창을 다시 열면 실제 자동 시작·업데이트 설정을 새로 확인한다. 키보드 상태는
설정 창에서 해당 항목을 펼쳤을 때만 조회한다. 업데이트 확인 요청은 즉시 진행
상태로 표시하고 중복 요청을 합친다. 상대보다 새로운 빌드만 전송할 수 있으며,
기기 등록이 기존 연결 때문에 제한될 때는 연결 해제가 필요하다는 안내를 표시한다.

자동 시작 변경 실패 시 영향을 받은 시작 설정과 복구 예약 작업의 복원을 검증하고,
복원 미확인은 오류로 유지한다. 자동 업데이트를 끈 경우는 다운로드 실패와 구분한다.
다운로드 완료와 자동 적용 대기는 구분한다. 자동 업데이트가 꺼져 있으면 파일을
보존하고 설정을 켜면 적용된다고 안내한다. 설정 조회 중이거나 읽지 못했을 때는
자동 적용을 예고하지 않는다. 실제 적용 직전에도 저장된 설정을 다시 확인한다.
취소 중에 자동 업데이트를 다시 켜거나 확인을 요청하면 취소 완료 후 새 확인을 한 번
진행한다. 다시 끄거나 앱을 종료하면 이 요청을 버린다. 설정값을 읽지 못한 경우는
꺼짐과 구분해 표시하고 변경을 막는다. 메인 화면과 설정 창은 같은 업데이트 안내를
사용하며, 설정 조회 중에는 이전 값으로 자동 적용을 예고하지 않는다.
재확인 작업의 실패·취소와 검증된 다운로드의 보존 상태를 따로 표시한다. 저장된
묶음은 새 확인과 적용 직전에 다시 검증한다. 앱을 켜며 설정을 읽는 동안에는 오류로
표시하지 않는다. 사용자가 새 버전을 직접 실행한 경우 교체의 준비·대기·실패 상태를
본문에 표시한다. 실패 후 다시 시도는 앞서 연 파일을 재검증하며 임의 경로를 받지 않는다.
새 버전 요청은 준비 작업 완료를 기다리지 않고 기존 창을 먼저 보여준다. 교체 상태
조회에 실패해도 마지막 확인 내용은 유지하되 현재 확인 불가임을 표시하고 재시도를
막는다. 실행 실패 후에는 저장한 복사본을 원래 묶음의 해시와 대조해 재사용한다.
변경된 복사본은 적용하지 않고 실패로 유지하며, 다시 시도만으로 복사본을 늘리지 않는다.
상대 앱 열기 요청은 기기별로 추적하며, 다시 선택하면 기존 요청 ID와 만료 시각으로
확인을 이어간다. 만료 기록 때문에 새 요청이 저장되지 않는 상황을 방지한다.

1. 두 기기는 명시적인 사용자 확인을 거쳐 서로를 신뢰한다.
2. source가 설정된 화면 가장자리에서 전환 의도를 감지한다.
3. destination이 입력 수신 준비를 확인한 뒤에만 source가 해당 물리 입력을 억제한다.
4. 활성 제어권은 한 번에 한 방향과 한 destination에만 존재한다.
5. 로컬 긴급 해제, 연결 단절, 절전, 잠금, 프로세스 종료 또는 상태 불일치가 생기면 기존 제어권을 폐기한다.
6. 양쪽은 눌린 키와 버튼을 해제하는 `ReleaseAll`을 수행한 뒤 `LOCAL` 상태로 수렴한다.
7. 재연결은 이전 제어권을 이어받지 않고 새 세션으로 시작한다.

선택적 보호 입력 서비스와 현재 빌드가 일치하는 설치 agent는 관리자 프로그램과
Windows PIN 창의 입력 경로를 제공한다. 서비스·고정 이미지·peer·새 lease 검증이
필요하며, PIN 값과 화면 내용은 수집하지 않는다. HP15↔GRAM13 g116~g118에서 일반 입력과
PIN 창 Esc·취소 클릭 성공이 사용자 보고로 확인됐다. PIN 값 입력 및 모든 보안 화면의
지원은 이 증거 범위에 포함하지 않는다. 설치·정식 배포의 남은 조건은 #16에 있다.

## 안전 불변조건

- destination 준비 전에는 source 입력을 막지 않는다.
- 합성 입력을 다시 상대에게 전달하지 않는다.
- 순서나 전달 여부가 불확실한 입력을 추측해서 재생하지 않는다.
- destination의 실제 로컬 입력이 원격 입력보다 우선한다.
- GUI는 실시간 입력 전달 경로와 제어권 소유자가 아니다. 현재 제품 projection은 Go/Win32다.
- 원시 키 입력, 마우스 궤적, 클립보드 또는 화면 내용을 로그에 남기지 않는다.

## 미결정 사항

- 지원 Windows 버전과 CPU 아키텍처
- 입력 캡처 방식: 저수준 hook 단독, Raw Input 결합, 또는 작은 native 모듈
- control payload 직렬화 형식
- transport 인증서의 제품 갱신 주기와 갱신 UX
- 화면 경계 감도, dwell, 압력과 지연 예산
- 긴급 해제 키 조합
- 설치 범위, 코드 서명, 방화벽 규칙

## 수용 기준

- Phase 0에서 실제 네 대의 대상 노트북으로 입력 캡처, 차단, 주입, 합성 입력 식별, 비정상 종료 복구를 검증한다.
- 한 기기 또는 네트워크를 강제로 끊어도 사용자가 로컬 입력을 잃지 않는다.
- 눌린 키와 버튼이 연결 장애 뒤 원격 기기에 남지 않는다.
- GUI 종료가 활성 입력 세션의 안전 종료를 방해하지 않는다.
- 진단 자료에 원시 사용자 입력이 포함되지 않는다.
- 관리 앱의 `진단 저장`은 이 PC의 새 진단을 저장하고 현재 연결 상대의 새 진단을 자동으로 요청해 이 PC에 모은다. 상대 PC에서 다시 누를 필요가 없다.
- 연결 상대는 에이전트의 현재 세션과 신뢰 정보로 결정한다. 과거에 받은 파일을 이번 요청의 성공으로 표시하지 않으며, 요청 ID가 일치하는 양쪽 새 파일을 확인한 뒤에만 완료로 표시한다.
- 연결 상대가 없으면 로컬 진단만 저장한다. 상대 응답 실패·수집 시간 초과·지원하지 않는 버전이면 로컬 저장과 상대 수집 실패를 구분해 알린다. 같은 요청의 상태 조회는 수집을 재시작하지 않는다.
- 진단 저장·상태 조회는 화면을 막지 않는다. 관리 앱을 다시 실행하면 보존된 수집 요청의 상태를 이어서 조회하며, `진단 폴더 열기`는 이번 수집의 로컬 파일을 선택한다. 저장 기록이나 실제 파일이 없으면 완료로 표시하지 않는다.

## 전제

현재 확인된 사실은 모든 대상 기기가 Windows라는 것뿐이다. 외부 설계 패키지가 제안한 Windows 11 x64, 관리자 권한, 공용 Wi-Fi 대체망, 키를 누른 상태의 전환 금지는 검증 전제로만 취급한다.
